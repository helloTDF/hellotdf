## How I work

### Bringing me in and what to expect

Before feature kickoff make sure you can answer these. If you cannot, that's exactly when to loop me in!

About the user
- [ ] Who are the customers in need of this feature (and what is their role, technical level, and task context)?
- [ ] What job are they trying to get done
- [ ] What does success look like for them?
- [ ] What do they know today? What are they uncertain or confused about?
- [ ] Are there multiple user types with competing needs on the same surface?

About the problem
- [ ] What user need or pain is this feature addressing?
- [ ] Is there existing research, feedback, or telemetry data I can review before kick off?
- [ ] What's in scope?
- [ ] Are there technical or data constraints that will limit design options?

About the work
- [ ] Are there related or prior design work I should align with?
- [ ] Is there an existing API, or architecture?
- [ ] Is there an existing design I'm reviewing, or are we in discovery?
- [ ] What fidelity is needed: rough exploration, full spec, or final redlines?
- [ ] Who is the engineering lead?

About decisions
- [ ] Who are our stakeholders?
- [ ] What decisions are already locked vs. still open?
- [ ] Are there stakeholder reviews or demos scheduled I need to design toward?

During the design phase
- Create 4-in-a-box calls (Design, PM, Content and Engineering)
- Post design artifacts in Figma, post videos and notify you in Slack and/or in Jira
- Ask questions directly on the artifact or in the associated ticket; not in DMs, so context is preserved and there is transparency
- Flag technical blockers early. I want to know about a constraint in week 1.

🏗️ Artifacts I produce 
- [ ] Design review reports
- [ ] Design renders
- [ ] Dashboard and analytics specifications
- [ ] User story and flow narratives
- [ ] (IA) Information architecture maps
- [ ] Flow scripts & prototypes
